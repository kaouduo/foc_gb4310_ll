# 接口与编码约定

更新日期：2026-10-31。

## 防御检查边界

约定靠**固定启动顺序、编译期绑定、调用方契约**保证，不在每层重复检查；真实硬件结果与可变范围继续检查。

不写：上下文（IPSR/PRIMASK/BASEPRI/调度器状态）判断、空指针校验、重复初始化保护、固定静态资源的创建结果检查、已由启动链保证的 DWT 就绪判断。
要写：时钟/PLL/Flash 等待周期等硬件状态、超时、频率最终校验；Flash 地址范围/长度/8 字节对齐/硬件忙/未擦除/读回校验；SPI 事务竞争、CRC、固定字段、设备状态；互斥量竞争结果。

ISR 或关中断上下文调用任务阻塞接口属于调用契约错误，由调用处修正，不用返回 `SYS_ERROR_BUSY` 掩盖。
`System_TimeMs` 保留任务/ISR 的 API 分流，那是功能分流而非防御检查。
主机测试验证有效调用、真实硬件失败、计数回绕与初始化执行顺序，不测试已删除的编程错误分支。

## C / C++ 混合

- BSP 与 application 的对外函数和全局实例声明用 `__cplusplus` 保护的 `extern "C"`；被 BSP 暴露的 `driver/led/led_base.h`、`driver/mt6826s/mt6826s_drv.h` 同样独立提供 C 链接声明。
- `common` 只放 C++ 能直接使用的类型/枚举/宏；业务不需要包含带 C11 原子的 porting 私有结构。
- 新增公共头：依赖头放 `extern "C"` 块**外**，函数与实例声明放块内。
- C++ 业务直接包含 `app_device_state.h`、`bsp_encoder.h`、`bsp_led.h`、`bsp_platform.h` 等，调用方不再自行包 `extern "C"`。
- 现有 `.c` 按 C23 编译，不改用 C++ 编译；`main` 保持 C，`.cpp` 按 C++23 编译。新增 `.cpp` 直接加入 CMake 固件源列表。统一配置位于 cmake/gcc-arm-none-eabi.cmake，关闭语言扩展并要求所选标准。
- C 接口不使用类、引用、模板或 STL 类型；跨边界用指针、枚举、普通结构。
- C++ 实现对外 C 接口时先包含声明头以继承 C 链接；类的非静态成员不能直接当 C 回调，用 context + 静态适配函数。
- 标准库线程与完整动态运行时尚未适配；FreeRTOS 堆不接管 `new`/`malloc`。

## 编码与仓库

- 自建文本 UTF-8（`.editorconfig` 指定），代码按根 `.clang-format` 格式化；第三方目录排除，不改、不格式化。
- 中文 Doxygen 注释，作者 `kaouduo`；不写"为什么这么做"的长篇理由注释（理由放文档/记忆），最多留一行指针。
- 提交日志 `type(module): 中文描述`，只描述最终功能，不追记对话中的临时修正。
- MR 标题 `[类型] 中文描述`，正文只写"修改原因 / 修改内容 / 验证"，对应 `.gitlab/merge_request_templates/Default.md`。
- 未经用户审核同意不执行提交或推送。`tests/` 仅本地保留并忽略，不入仓库。
